# Decisiones del proyecto

- Usar Firebase por instrucción expresa de la usuaria: Authentication, Firestore, Cloud Functions y Hosting; Storage para artefactos cuando corresponda.
- Mantener UI y documentación de negocio en español.
- Primera cobertura: facturas y notas crédito/débito, diez empresas asumidas.
- Nunca presentar borradores como facturas emitidas, habilitación aprobada o cumplimiento certificado.
- En el modo Functions, mantener operaciones y cálculos en servidor. Por decisión de conservar Spark, el modo gratuito permite cálculo cliente con verificación obligatoria de importes en Security Rules del servidor, hasta tres conceptos. Probar aislamiento y rechazar importes alterados.
- No guardar certificados ni claves privadas en código, configuración web o repositorio.
- Mantener el entorno de demostración `demo-facturacion` separado de proyectos reales.

- Flujo vigente autorizado: desarrollar y mostrar el código local conectado a Authentication y Firestore REALES. Usar `bash scripts/local.sh cloud` (opción predeterminada), http://localhost:5504, dist-cloud. Los cambios de datos que la usuaria haga en esa interfaz afectan Firebase real.
- Preferencia vigente desde el 2026-10-07: publicar en Firebase cada cambio terminado. Para cambios visuales o de cliente, desplegar Hosting después de aprobar pruebas; si el cambio requiere reglas o índices, validar y desplegar también esos componentes. Informar siempre el alcance. Esta autorización no cubre operaciones masivas o destructivas sobre datos reales.
- Conservar emuladores para pruebas automatizadas y datos ficticios; no sembrar datos de prueba en el proyecto real. dist-cloud, dist de emuladores y dist-release están separados.
- Roles publicados: organizations/{nit}; platformAdmin solo mediante entorno privilegiado, nunca desde el navegador. Migración completada y verificada el 2026-09-30. Los originales bajo workspaces se conservan como archivo de solo lectura para su propietario.
